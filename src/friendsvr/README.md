# 好友服务

好友包含好友管理和好友推荐子服务，客户端接入由 lobbysvr 负责。

## friendsvr-management

好友管理负责好友的增加、删除、修改、订阅，以及邀请的发起、同意和否决。
每个用户的好友对象是分布式事务参与者，事务协调由 `distributed_transaction` 组件负责。

普通事务准备成功前保存参与者状态；提交和拒绝修改内存后通过路由系统的快速保存机制入库。
SDK 默认事务委托等待参与者响应，准备阶段的保存失败会返回给事务客户端进行重试。
普通事务和 `force_commit` 的选项在首次读取时从配置创建，之后作为进程内共享的只读对象使用。
事件编号由好友对象在事务执行时分配，调用方不能指定编号。入库时将已分配的编号写入运行中事务的参与者数据，恢复后重放使用原编号。
SDK 的 `force_commit` 选项沿用事务组件的 best-effort 语义，不提供普通事务的协调者记录和故障恢复保证；与运行中或已完成事务使用同一 UUID 时会被拒绝。

路由归属、版本和保存时间统一存储在 `table_friend.router_lock` 中，路由查询读取整个锁字段。
释放路由时保留该字段并将持有进程 ID 写为 0，使数据库覆盖此前的非零进程 ID。

首次订阅使用空检查点时接收完整快照。断线重订沿用请求中的检查点；没有缺失事件时不重复发送快照，编号高于检查点且尚在内存 WAL 中的事件可增量补发。
好友对象装载时将 WAL 最后裁剪的事件 ID 至少设为 1，以触发首次快照；保存时记录该序号，恢复时用它与已有序号一起确定新事件 ID 的起点。
事务事件编号按实际执行顺序分配；准备顺序与提交顺序不同时，客户端仍可沿用已收到的最大事件编号作为检查点。
旧快照中已经分配编号的运行中事务会沿用原编号重放，避免改变部分执行后的幂等判断。
完整快照不包含参与者私有事务数据；快照覆盖的事件不会在同一批通知中重复发送。
过期好友和邀请的清理也会下发删除事件。好友未设置过期时间时长期有效。

礼物字段仅作数据层预留，不提供礼物业务入口，管理事务拒绝礼物事件。

### 单元测试

`friendsvr-management-unit-test` 使用离线 RPC 测试环境，通过生成的 SDK 和真实 action 验证好友、邀请、
持久化失败重试、路由归属、事务恢复及订阅通知。数据库、服务发现和传输使用内存适配器，
这些测试不代表真实 Redis、协调者和多节点网络的部署验收。

```powershell
cmake --build <BUILD_DIR> --target atf4g-co-friendsvr-management-unit-test --parallel <JOBS>
ctest --test-dir <BUILD_DIR> -R friendsvr-management --output-on-failure -V
```
