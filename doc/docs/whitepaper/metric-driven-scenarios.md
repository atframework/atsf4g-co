# 指标驱动的应用场景

以下三个场景用于举例说明基于指标的通用动态策略管理。具体业务指标与决策逻辑由使用方接入。

## 基于指标的通用动态策略管理

这类需求都需要聚合多个服务的指标，由控制节点决策，再将策略下发给相关服务。
框架复用 OpenTelemetry 指标上报、Prometheus Query 聚合查询、主控节点选择和 etcd 策略下发能力。

接入自定义策略的主要步骤是：

1. 配置指标含义。
2. 注册指标上报。
3. 注册决策算法。
4. 监听策略变化。

指标采集与策略接口见[可观测性与动态策略](observability-policy)，服务副本控制见[HPA 控制器](hpa-controller)。

## 场景一：按订单量调整订单撮合副本

交易行订单量变化会改变订单撮合服务的负载。业务可以将订单量作为指标，用于调整撮合服务的副本数。

该场景关注订单量与服务规模的关系。订单量的统计规则和副本调整策略由业务定义。

## 场景二：按搜索行为分布调整索引与视图

交易行搜索包含多种标签、范围与排序条件，难以为所有条件组合建立索引。
搜索行为的分布可以帮助识别热点条件，用于调整索引量和动态视图数量。

该场景关注缓存命中率与视图开销的平衡，以及全局索引搜索开销与订单更新时维护视图索引开销的平衡。
具体调整策略由业务结合搜索行为指标确定。

## 场景三：按进战斗频率调整匹配与房间控制

玩家进入战斗的频率和数量可用于控制匹配撮合服务的分布，以及战斗房间的排队和预创建量。

匹配服务节点调整与房间控制分别对应服务规模和业务参数，可以通过通用动态策略管理接入各自的决策逻辑。
具体指标含义和控制规则由业务定义。
